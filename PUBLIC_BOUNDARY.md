# Public disclosure boundary

This repository is a **public engineering case study**, not an open-source release and not a mirror of the private implementation repository.

## Intentionally public

- the problem being addressed;
- the outcome-first system boundary;
- selected engineering trade-offs;
- the AI-assisted workflow at a non-sensitive level;
- verification philosophy and uncertainty handling;
- high-level technical context;
- current status and explicit non-claims.

## Intentionally private

- application source code;
- internal prompts or agent instructions;
- exact schemas, contracts and verifier implementations;
- private repository paths, commit hashes and internal document names;
- credentials, secrets and environment configuration;
- raw evidence, private fixtures and detailed evidence formats;
- unpublished APIs or internal endpoints;
- proprietary evaluation logic;
- private roadmap sequencing and commercial experiments;
- implementation details that would materially reproduce the system.

## Why

The useful employer signal is the reasoning: **what should be measured, what evidence is strong enough, where uncertainty belongs, and what the system must refuse to overclaim**.

Public does not mean open source. No license to the private implementation is granted or implied by this case study.
